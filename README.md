# Tax & Milestone Tracker (TMT)

## Overview
The Tax & Milestone Tracker (TMT) is a full‑stack web application that enables
- **User management** with JWT authentication and refresh tokens.
- **Client directory** with tax obligations and payment milestones.
- **Receipt uploads** using magic‑byte validation and streaming.
- **Dashboard** with metrics, deadline alerts, and CSV exports.
- **Approvals & Settings** workspaces (to be implemented next).

## Prerequisites
- **Node.js** >= 20 (tested with v24.18.0)
- **npm** (comes with Node)
- **PostgreSQL** >= 15
- **Git**
- **Windows PowerShell** (or cmd) – all commands are Windows‑compatible.

## Setup
1. **Clone the repository**
   ```powershell
   git clone <repo‑url>
   cd student-6apsi-2215-xxenderconxx\project\TMT_project
   ```
2. **Install dependencies**
   ```powershell
   npm install
   ```
3. **Create an `.env` file** – copy the example and fill in your secrets:
   ```powershell
   copy .env.example .env
   # Edit .env
   notepad .env
   ```
   Required variables:
   - `PORT` – server port (default 5000)
   - `DATABASE_URL` – e.g. `postgresql://postgres:YOUR_PASSWORD@localhost:5432/tmt_db`
   - `JWT_SECRET` – strong random string
   - `CLIENT_ORIGIN` – usually `http://localhost:5173`
4. **Create the database** (already done by you, but documented here):
   ```powershell
   createdb tmt_db
   psql -d tmt_db -f schema.sql
   psql -d tmt_db -f seed.sql
   ```
5. **Run the development servers** (backend + frontend proxy)
   ```powershell
   npm run dev
   ```
   - Backend runs on `http://localhost:5000`
   - Vite dev server runs on `http://localhost:5173` and proxies `/api` to the backend.

## Scripts
- `npm run dev` – start backend and Vite dev server (concurrently).
- `npm run start` – start only the backend (production mode).
- `npm run build` – build the React app for production.

## Testing
Currently no automated tests are present. When new components (Approvals, Settings) are added, consider adding:

## Security Checklist (quick reference)
- All SQL uses parameterised queries.
- File uploads validated via magic‑byte inspection (`file-type`).
- JWT secret stored in `.env` and never committed.
- Refresh tokens are hashed before persisting.
- Error responses omit stack traces.
- CORS limited to `CLIENT_ORIGIN`.
